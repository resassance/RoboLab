# RoboLab

RoboLab подключается к агенту робота, запускает разрешённый алгоритм и показывает состояние процесса и журнал. Для работы на ПК без Raspberry Pi доступен **Mock Robot**. Учебные скрипты, полевые журналы и конфигурация Yahboom хранятся в отдельном проекте.

- [Аудит Yahboom и точки интеграции](docs/INTEGRATION_AUDIT.md)
- [Архитектура и контракт агента](docs/ARCHITECTURE.md)

## Запуск на ПК

Нужен Python 3.11 или новее. Выполняйте команды из корня RoboLab в двух терминалах.

**Linux, агент** (bash или sh)

```sh
python3 -m venv .venv-agent
.venv-agent/bin/python -m pip install ".[agent]"
export ROBOLAB_TOKEN="$(.venv-agent/bin/python -c 'import secrets; print(secrets.token_urlsafe(32))')"
printf '%s\n' "$ROBOLAB_TOKEN"
.venv-agent/bin/robolab-agent
```

**Linux, клиент**

```sh
python3 -m venv .venv-client
.venv-client/bin/python -m pip install ".[client,desktop]"
.venv-client/bin/robolab-client
```

**Windows, агент** (PowerShell)

```powershell
py -3 -m venv .venv-agent
.\.venv-agent\Scripts\python.exe -m pip install ".[agent]"
$env:ROBOLAB_TOKEN = & .\.venv-agent\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(32))"
$env:ROBOLAB_TOKEN
.\.venv-agent\Scripts\robolab-agent.exe
```

**Windows, клиент** (PowerShell)

```powershell
py -3 -m venv .venv-client
.\.venv-client\Scripts\python.exe -m pip install ".[client,desktop]"
.\.venv-client\Scripts\robolab-client.exe
```

1. Оставьте адрес `http://127.0.0.1:8765`, вставьте токен из первого терминала и нажмите **Подключиться**.
2. Выберите **Mock Robot**, нажмите **Запустить** и дождитесь строки «Шаг симуляции». Окно покажет PID и длительность процесса.
3. Нажмите **Остановить** и дождитесь статуса «Остановлен». На Linux симулятор обрабатывает сигнал и завершает работу с кодом 0 после штатной остановки. Если его не остановить, он завершится примерно через 40 с.

Первый запуск десктопного Flet может скачать соответствующий движок. Для проверки интерфейса в браузере установите `.[client,web]` и выполните `robolab-client --web`. Сервер интерфейса также слушает только loopback.

Агент по умолчанию слушает только `127.0.0.1:8765`. Для подключения с другого устройства укажите интерфейс через `--host` и адрес этого интерфейса в клиенте. Для передачи управляющих запросов за пределами доверенной сети используйте TLS или защищённый туннель. Токен нужен для HTTP и WebSocket. Для Raspberry Pi подготовлен [локальный адаптер Yahboom и порядок проверки на стенде](docs/YAHBOOM.md).

## Настройка Mock Robot

Откройте **Параметры**, чтобы выбрать сценарий, количество шагов, интервал и метку запуска. В сценарии `scan` доступно число точек сканирования. Включите **Диагностика DEBUG** для подробностей в журнале. Предпросмотр показывает аргументы в формате команды POSIX.

Кнопка **Применить** сохраняет текущие значения для следующих запусков. Чтобы сохранить именованный вариант, введите название и нажмите **Сохранить пресет**. Выберите его в разделе **Пресеты** и нажмите **Применить**. Последняя конфигурация и пресеты хранятся на клиенте отдельно для каждого адреса агента и скрипта.

У Mock Robot есть и прямой запуск через argparse:

```sh
python -m examples.mock_robot --scenario scan --scan-points 4 --steps 3 --interval 0.2 --verbose
```

## Просмотр камеры

На ПК можно включить [тестовую камеру OpenCV](docs/CAMERA.md) и проверить четыре режима изображения без Raspberry Pi. Для Yahboom устройство задаётся локально. Кнопка **Камера** открывает настройки, а **Начать просмотр** запускает передачу кадров.

## Телеметрия и эксперименты

В клиенте кнопка **Телеметрия** открывает текущие показатели агента и живой график. **Эксперименты** открывают историю, сравнение запусков и экспорт в JSON или CSV. Формат метрик и настройка постоянного хранения описаны в [инструкции по экспериментам](docs/EXPERIMENTS.md).

## Передача файлов на робота

Чтобы открыть для загрузки домашнюю папку пользователя `pi` и её подкаталоги, добавьте `--file-root` к команде запуска агента на Raspberry Pi.

```sh
robolab-agent --yahboom-config /etc/robolab/yahboom.local.json --file-root 'Домашняя папка=/home/pi'
```

Подключитесь к агенту, откройте **Файлы**, выберите папку на роботе и файл на устройстве, затем нажмите **Отправить**. Пользователю агента нужны права прохода и чтения для просмотра папок и права записи в папку назначения. Символические ссылки пропускаются. При OverlayFS выбирайте папки на постоянном томе, если файлы должны сохраняться после перезагрузки.

Чтобы добавить несколько рабочих папок, повторите `--file-root` с другими именами. Исходный лимит — 32 МиБ на файл. Его можно изменить через `--max-upload-mib`. При совпадении имени RoboLab покажет конфликт. Готовый файл появляется после полной передачи.

На Linux для системного выбора файла нужны XDG Desktop Portal и бэкенд рабочего стола с поддержкой FileChooser. В Android выбор открывается системным диалогом документов.

## Сборки клиента

Для Linux, Windows и Android предусмотрены отдельные сборки. Порядок запуска, локальной сборки и выпуска описан в [инструкции по релизам](docs/RELEASES.md).

## Проверки разработки

```sh
python -m pip install -e ".[agent,client,dev]"
python -m pytest -q
ruff check .
ruff format --check .
```

В наборе тестов валидация параметров и их передача в CLI, запуск процесса, передача stdout/stderr, остановка, восстановление журнала по номеру сообщения, отказ запуска и блокировка одновременного старта. Сценарий клиента можно пройти через Flet по шагам выше. Windows, Android и Raspberry Pi требуют отдельных проверок.
