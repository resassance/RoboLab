# Аудит интеграции с Yahboom Raspberry Pi 4WD Car

Аудит выполнен 23 ноября 2026 г. по локальному снимку `yahboom-4wd`. В корне есть пустой каталог `.git`, поэтому `git status` не определяет ветку и состояние индекса. В самом снимке `AGENTS.md` не найден. Исходники, журналы и архивы Yahboom при аудите читались локально.

## Точки входа и конфигурация

| Файл в снимке | Роль |
| --- | --- |
| `project/robot_navigation.py` | Основной CLI. Статические замеры и анализ: `distance`, `scan`, `plan`, `ir`. Движение: `turn`, `drive`, `auto`. Камера и её приводы: `color`, `snapshot`, `inspect`, `camera-pose`. Режим по умолчанию — `scan`. |
| `project/camera_diagnostics.py` | Проверка узлов, прав и возможностей V4L2, включая `v4l2-ctl` и `fuser` при их наличии. Параметры `--device`, `--output`; захват кадров и GPIO не запускаются. |
| `project/navigation.py`, `trajectory.py`, `obstacle_geometry.py` | Решения навигации, оценка траектории и геометрия препятствия. Внешней точкой запуска остаётся основной CLI. |
| `project/robot_config.json`, `color_config.json`, `snapshot_config.json` | Настройки оборудования, распознавания и съёмки. Параметры конкретного робота следует хранить на устройстве. |
| `reference/main2.py`, `outputs/`, `logs/`, `documents/` | Исторический скрипт, учебные сборки, полевые журналы и материалы занятий. В дерево и историю RoboLab они не входят. |

Группы флагов выделены по `argparse` и проверкам после `parse_args`.

| Группа | Типы и ограничения в текущем CLI |
| --- | --- |
| Режимы | `--mode` и `--obstacle-mode` — перечисления. Вариант препятствия `camera` применяется с `auto`. |
| Числа | `--cycles` — положительное целое. Время работы — число в диапазоне (0, 600] с, время ручного проезда — (0, 2] с, модуль угла поворота — (0, 90]°. Углы камеры и ручная дистанция — числа с контекстной проверкой. |
| Пути | `--config`, `--log-dir`, `--color-config`, `--snapshot-config` — строки путей. Для удалённого управления пути следует назначать локально в конфигурации агента. |
| Переключатели | `--ir-assist`, `--ir-turn-guard`, `--slow`, `--use-ir`, `--video`, `--position-camera`, `--save-snapshots`, `--allow-blue-push`, `--confirm-camera-alignment`. Для них действуют ограничения по режимам и совместимости. |
| Устройства | `--ir-pins` имеет собственный преобразователь, `--camera-device` принимает индекс или путь, `--camera-backend` — `default` или `v4l2`, `--port` — целое. |

Отдельный манифест позволит описать проверки, которые выходят за пределы синтаксиса argparse. Для будущего получения подсказок из исходника подходит разбор AST без импорта с поддержкой только статических литералов. Динамические значения и зависимости должен задавать манифест. Текущий агент для формирования списка скриптов читает собственный реестр и не открывает исходники Yahboom.

## Аппаратура, камера и остановка

- Движение, дальномер, ИК и PWM сервоприводов зависят от `RPi.GPIO`. OpenCV и NumPy нужны для распознавания и отдельных снимков. Flask нужен для существующего видеопотока. README Yahboom указывает Python 3.7+ для самих скриптов. Версия Python на доступном при интеграции устройстве требует отдельной проверки.
- `color` включает распознавание и Flask-поток. Отдельный `--video` работает в совместимых режимах. `snapshot` и `inspect`, а также `auto --obstacle-mode camera`, получают серии кадров через отдельный процесс `camera_worker.py`. Родитель ждёт завершения процесса и освобождения камеры. CLI запрещает `--video` вместе с режимами снимков.
- `robot_navigation.py` перехватывает SIGINT и SIGTERM после инициализации, выставляет флаг остановки и закрывает аппаратные компоненты в `finally`. Для адаптера нужно подтвердить, что двигатели действительно останавливаются при обрыве связи или сбое, включая фазу запуска. Принудительное завершение процесса не гарантирует выполнение GPIO-очистки. Материалы снимка содержат отдельные полевые проверки движения и съёмки, но не подтверждают полную проверку RoboLab или физический возврат робота на линию.
- Сторонние процессы, включая официальный сервер и прямые запуски из SSH, могут пользоваться теми же GPIO и V4L2. Ограничение запусков внутри сервера покрывает только запуски этого сервера. Перед аппаратной интеграцией нужно определить взаимное исключение и проверить, кто владеет устройствами.

## Логи и данные Raspberry Pi

`SessionLog` пишет построчно `events.jsonl` и `session.log` в каталог запуска. У событий есть счётчик, UTC-время, время от старта и тип. В stdout сразу выводятся человекочитаемые строки, кроме сырых замеров `distance_raw`. Адаптер сможет собирать stdout и stderr, а после согласования схемы читать JSONL без дублирования событий. Путь задаётся `--log-dir`; для съёмки также нужны временный каталог и место под снимки.

Режим OverlayFS на Raspberry Pi по рабочему снимку и имеющимся журналам определить не удалось. Показания файловой системы ПК к роботу не относятся. При доступе к Pi режим можно проверить командами чтения, подставив фактический каталог данных. При использовании временного верхнего слоя изменения теряются после перезапуска. Для будущей SQLite и логов нужен явно выбранный постоянный writable-том.

```sh
cat /etc/os-release
python3 --version
findmnt -T / -o TARGET,FSTYPE,OPTIONS
findmnt -T /var/lib/robolab -o TARGET,FSTYPE,OPTIONS
```
