# Подключение Yahboom Raspberry Pi 4WD Car

Адаптер работает на Linux. Параметры запуска и испытания на ПК проверяются с имитацией GPIO. На Raspberry Pi 4B потребуется проверить права, входы разрешения драйвера и фактическую остановку колёс на вашей сборке.

## Локальная конфигурация

Установите RoboLab отдельно от Yahboom. У агента требуется Python 3.11+, у существующего CLI Yahboom может быть собственный Python. Для отключения моторов этот интерпретатор должен видеть классический `RPi.GPIO` в системном окружении или в своём virtualenv, включая запуск с `-I`. Дайте одному пользователю службы доступ к GPIO, локальной конфигурации и каталогу журналов.

Сохраните локальный JSON вне дерева репозитория, например в `/etc/robolab/yahboom.local.json`. Укажите фактические абсолютные пути. Для первого запуска оставьте `allow_motion` выключенным.

```json
{
  "python": "/usr/bin/python3",
  "script_dir": "/opt/yahboom/project",
  "config_file": "/var/lib/robolab/robot_config.local.json",
  "log_dir": "/var/lib/robolab/yahboom-logs",
  "lock_file": "/run/robolab/yahboom.lock",
  "allow_motion": false
}
```

Для отдельного просмотра добавьте в этот файл `"camera_device": "/dev/video0"` и проверьте доступ пользователя службы к устройству и OpenCV. [Подробности настройки камеры](CAMERA.md)

В `script_dir` должен быть читаемый `robot_navigation.py` вместе со своими модулями. `log_dir` и каталог файла блокировки должны существовать. В системе с OverlayFS проверьте постоянное монтирование для конфигурации и журналов. Замок можно держать в `/run`, где хранятся данные текущей загрузки.

Подготовьте `/run/robolab` для того же пользователя, запустите агент с настроенным `ROBOLAB_TOKEN` и подключите Flet по защищённому каналу. По умолчанию агент слушает loopback. Для теста на ПК с SSH-доступом подойдёт локальный туннель на порт 8765.

```sh
robolab-agent --yahboom-config /etc/robolab/yahboom.local.json
```

## Подключение по SSH

1. На компьютере откройте RoboLab. Выберите **SSH к Raspberry Pi**, введите адрес Pi, порт SSH (обычно `22`), имя пользователя и пароль. При первом входе сверьте отпечаток. Для ключа Ed25519 команда на Pi — `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub`.
2. Откройте **Файлы**. Выберите каталог в домашней папке пользователя SSH и отправьте файл. В этом же разделе можно создать папку и перетащить файлы или папки в настольную сборку для Linux или Windows. Для передачи сервер Pi должен поддерживать SFTP.
3. Нажмите **Работа → Подготовить эксперименты**. Если на Pi уже работает агент на `127.0.0.1:8765`, клиент подключится с его токеном. Иначе он передаст файлы агента по SSH и запустит его на локальном порту Pi. Для подготовки нужны Python 3.11 или новее и разрешённый проброс порта. Готовые сборки передают зависимости по SSH для Raspberry Pi OS Bookworm (CPython 3.11) и Trixie (CPython 3.13) на 32- и 64-битных системах. Доступ к PyPI и `python3-venv` на Pi для этого не требуются. При запуске клиента из исходников нужны уже установленные совместимые зависимости на Pi. Клиент не повышает права.
4. Чтобы подключить дальномер Yahboom без готовой конфигурации, укажите абсолютный путь к существующей папке с `robot_navigation.py` и `robot_config.json`. Пользователю SSH нужны доступ к GPIO и `RPi.GPIO` в системном Python. Остановите другие программы управления перед испытанием. Автоматически созданная конфигурация разрешает дальномер и оставляет движение выключенным. Пустое поле использует существующую конфигурацию, если она есть. Иначе откроется стенд **Mock Robot**.

### Для заранее установленного агента

Если нужно запустить агент самостоятельно, на Raspberry Pi один раз создайте файл токена от имени того же пользователя, под которым вы подключаетесь по SSH и запускаете агент.

```sh
python3 -c 'import os, secrets; from pathlib import Path; os.umask(0o077); p = Path.home() / ".config/robolab/token"; p.parent.mkdir(parents=True, exist_ok=True); p.open("x").write(secrets.token_urlsafe(32))'
robolab-agent --token-file ~/.config/robolab/token --yahboom-config /etc/robolab/yahboom.local.json --file-root 'Домашняя папка=/home/pi'
```

Агент принимает токен из обычного файла без символических ссылок. Оставьте агент на `127.0.0.1:8765`. Клиенту нужны SFTP и проброс порта через SSH.

Кнопка **Выключить Raspberry Pi** сначала запрашивает аварийную остановку у агента. После подтверждения отключения приводов агент временно блокирует сброс аварийной остановки, а RoboLab выполняет через SSH `sudo /usr/sbin/poweroff`. Введите пароль sudo в диалоге, если его требует настройка робота. Если SSH оборвётся до получения статуса команды, RoboLab попросит проверить состояние Pi.

## Взаимное исключение

Остановите официальный сервер управления Yahboom и другие программы, работающие с GPIO, перед использованием адаптера. Локальные запуски учебного CLI и сервисы должны брать тот же `flock` тем же пользователем. Пока владелец удерживает замок, агент отклоняет старт и аппаратное переключение ENA/ENB. Файл замка сохраняют на весь период работы, включая интервалы между запусками.

Пример прямой диагностики с тем же замком и путями:

```sh
flock -n /run/robolab/yahboom.lock /usr/bin/python3 /opt/yahboom/project/robot_navigation.py \
  --mode distance --cycles 1 \
  --config /var/lib/robolab/robot_config.local.json \
  --log-dir /var/lib/robolab/yahboom-logs
```

При запуске агента как службы systemd назначьте отдельную группу процессов службы через стандартный `KillMode=control-group`; задайте `RuntimeDirectory=robolab`, сохраните каталог при остановке и задайте время остановки с запасом для завершения процесса и проверки GPIO. Для обработки аварийного завершения агента можно добавить `ExecStopPost` с тем же замком и интерпретатором. Проверьте пути и поведение этой команды на стенде с отключённым питанием моторов.

```ini
[Service]
RuntimeDirectory=robolab
RuntimeDirectoryPreserve=yes
KillMode=control-group
TimeoutStopSec=12s
ExecStopPost=/usr/bin/flock -n /run/robolab/yahboom.lock /usr/bin/python3 -I /opt/robolab/agent/motor_off.py
```

## Проверка на роботе

1. Сверьте BCM16 и BCM13 с входами ENA и ENB на конкретной плате. Обеспечьте доступ к независимому выключателю питания приводов. Начните с отключённого питания моторов, затем проводите проверки с поднятыми колёсами.
2. Выберите **Дальномер Yahboom** и запустите несколько измерений. Проверьте показания, статус процесса и журнал Yahboom. Успешное завершение обновляет статус программной проверки ENA/ENB.
3. Во время запуска нажмите **Остановить**. Затем повторите с кнопкой **Аварийная остановка** и отдельным испытанием разрыва связи. Агент отсчитывает 4 секунды от последнего подтверждения связи; дополнительно занимает время завершение группы и перевод входов в LOW. Измерьте реальное время останова на стенде.
4. Убедитесь, что после аварийной остановки новый аппаратный запуск блокируется. **Снять блокировку** выполняет повторную проверку ENA/ENB и разрешает следующий ручной запуск.
5. Проверьте конфликт на дальномере, удерживая общий `flock` другим процессом. Агент должен сообщить, что оборудование занято. Прежний процесс сохраняет управление до своего завершения.
6. Включайте `allow_motion: true` только после этих проверок и проверки самого алгоритма движения на стенде. Профиль объезда использует ультразвук и длится от 1 до 20 секунд по параметру запуска.

Статус подтверждает программную установку и чтение уровня GPIO. При зависании ОС, отказе питания, несовпадении разводки или неисправности драйвера нужен независимый способ обесточить приводы.

- [Исходник GPIO.input в классическом RPi.GPIO](https://sources.debian.org/src/rpi.gpio/0.7.1~a4-1/source/py_gpio.c/#L1587)
