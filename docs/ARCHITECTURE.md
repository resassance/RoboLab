# Архитектура RoboLab

RoboLab имеет собственное дерево и историю Git. Учебные алгоритмы, полевые журналы и конфигурация Yahboom хранятся отдельно. Для будущего аппаратного адаптера локальный оператор сможет назначать скриптам доверенные идентификаторы и абсолютные пути. Приложение на клиенте никогда не передаёт агенту путь или команду оболочки.

## Этап 1

- `agent/` содержит FastAPI, реестр с одним поставляемым примером и управление дочерним процессом. Команда собирается из `sys.executable` и фиксированного файла, отдельными аргументами. Исполняемый пример не читает GPIO и камеру.
- `client/` содержит Flet и асинхронный транспорт. Пользователь вводит адрес и токен, выбирает скрипт, запускает или останавливает его, видит текущее состояние и журналы.
- `common/` содержит модели Pydantic для API. Фаза, PID, UTC-время, прошедшее время и код завершения передаются независимо от текста журнала.
- `examples/` содержит оригинальный Mock Robot. `tests/` проверяет API, процесс и поток на ПК.

На старте агент слушает loopback. Аутентификация HTTP и WebSocket использует заголовок `Authorization: Bearer …`. Токен читается из окружения агента и вводится в Flet. Для сети с недоверенными участниками нужен TLS или защищённый туннель. HTTP передаёт токен открытым текстом. Захват и трансляция камеры в первом этапе отсутствуют.

## Контракт

| Канал | Назначение |
| --- | --- |
| `GET /health` | Проверка связи, версии контракта и типа агента. |
| `GET /scripts` | Идентификатор, название и описание доступного скрипта. |
| `POST /runs` | Запуск по идентификатору из реестра. |
| `POST /runs/{run_id}/stop` | Остановка конкретного запуска. |
| `WS /events` | Состояние последнего запуска, сообщения stdout/stderr и периодические обновления. |

Единственный агент с одним worker управляет одним процессом за раз. Запуски сериализуются, конфликт получает HTTP 409. Остановка посылает сигнал и даёт процессу время штатно завершиться, после таймаута процесс принудительно завершается. Агент дочитывает журналы и возвращает итоговый статус и код. При отключении UI процесс продолжает работу до остановки, завершения программы или штатного выключения агента. Пример также имеет собственный предел времени.

Агент держит в памяти только последний запуск и до 300 его строк. Каждая строка имеет номер в рамках запуска. После обрыва клиент повторно проверяет связь и открывает поток с последним подтверждённым номером. При переполнении буфера интерфейс отмечает пропуск. Если за время обрыва стартовал новый запуск, клиент принимает его состояние и новый журнал. Команды запуска и остановки автоматически не повторяются. Клиент получает актуальное состояние по восстановленному потоку.

## Дальнейшая интеграция

1. Добавить манифесты флагов, типизированную проверку аргументов и пресеты. Сканирование argparse ограничить статическим разбором. Манифесты учебных скриптов устанавливаются локально на Pi.
2. Проверить запуск доверенных процессов в окружении с подходящим Python и правами к устройствам. Для прямого CLI и агента нужен общий способ захвата ресурсов либо переключение режимов через службу. Для моторов нужны проверка очистки GPIO, аварийная остановка и проверка отказов на роботе.
3. Привязать подписку на изображения к отдельному действию пользователя. Если алгоритм уже владеет камерой, он отдаёт копии кадров через адаптер. При отсутствии такого владельца отдельный захват требует эксклюзивного доступа. Выход из просмотра прекращает передачу кадров, сохраняя захват, если он требуется алгоритму.
4. Хранить длительные журналы, SQLite и экспорт на заданном постоянном томе. Временная работа симулятора допустима и при OverlayFS. Перед включением истории проверить монтирование и сохранение данных после перезапуска Pi.

Клиент и агент имеют независимые наборы зависимостей. Целевой минимум RoboLab — Python 3.11, чтобы сохранять возможность тестирования на Raspberry Pi OS Bookworm. Реализация рассчитана на отдельное современное окружение агента, даже если внешний CLI требует более старого Python. Flet умеет упаковывать приложения для Linux, Windows и Android. Сборки и проверка пакетов на устройствах относятся к этапу релиза.
